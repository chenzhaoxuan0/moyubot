# 25 · 品牌设计简报（MoyuBot）

> 供品牌设计起步使用。**不含配色**——现行主题色是阶段性实现，不是品牌结论。

---

## 一、这是什么

**MoyuBot 是本地优先的个人统一工作台：用一个界面管理多个「单元」，让多家开源 Agent CLI
在其中平等切换。**

现成标语：**「bot 干活，你摸鱼。」**（`README.md` 首屏）

一句话展开：一个文件夹就是一个单元（bot 或项目），工作台只是这个文件夹的投影——
人设住 `SOUL.md`、规矩住 `AGENTS.md`、长期事实住 `MEMORY.md`，用户在编辑器里改文件，
界面会跟着变。已有文件夹只「认领」不搬家，资产零迁移。

---

## 二、给谁用

个人开发者 / 独立工作者，重度使用多个 coding agent。不是团队产品，不做多用户、不做云同步。

痛点：现有 agent 产品只实现一种身份模型，把「员工」和「开发」割裂成两类软件，
迫使用户来回切换。MoyuBot 用一个界面同时承载两种：

| 形态 | 含义 | 比喻 |
|---|---|---|
| **bot（数字员工）** | 一类事务的专人专事，长期重复干活 | 招聘 |
| **项目** | 一个开发项目，多 agent 按角色分工 | 组队施工 |

两者是同一原语的两种视图，不是两套系统。

---

## 三、核心能力（品牌可选的卖点）

- **13 家 Agent CLI 平等切换**（Claude Code / Codex / pi / OpenCode / MiniMax Code 等），
  谁都不是附属品；不 fork、不绑架上游。
- **一处干活，处处查看**：桌面、网页、手机、飞书 / Telegram / Discord / 微信看到的
  是同一个会话，只差一枚来源徽标。
- **自主但有闸门**：空闲时心跳自己提议干待办，但启动前必须过**确认门**，干完要你
  **验收**；被忽略就休眠。
- **AI-native**：界面能做的每件事，`aw` 命令行 / `POST /rpc` 都能做——工作台本身
  也是 agent 可以驾驶的对象。
- 另有：记忆三柱、联网搜索、出图、浏览器 / 电脑控制（带急停）、Git 工作树、定时自动化。

---

## 四、差异化（品牌要占的位置）

1. **一个界面，两种身份** —— 不逼你在「员工软件」和「开发软件」之间来回切。
2. **执行器平等** —— 反锁定，不做某家的附属品。
3. **本地优先、零迁移** —— 你的文件始终是你的。
4. **透明** —— 这是全项目最一致的人格：探测失败不谎报成功、模型下线如实告知而绝不
   静默偷换、做不到的硬边界直接写进提示。它承诺的不是「更聪明」，是**「不瞒你」**。

---

## 五、调性

**关键词：克制 · 本地 · 透明 · 专业工具感 · 一点玩世不恭**

- 主体是**专业工具**：可靠、可预测、不喧哗——用户每天盯它 8 小时。
- 「摸鱼」提供情绪张力和玩心，但不能压过工具的可信度。
- **避免**：花哨拟物、赛博朋克霓虹、拟人化萌宠（与「基础设施」冲突），
  以及任何暗示「你在偷懒」的视觉暗示。

体验上已有两条纪律可继承：**渐进披露**（不用时不占版面，功能不因空而消失）、
**身份靠头像**（同一个 bot 永远长一样，靠颜色 × 形状的稳定组合）。

---

## 六、命名与标识约束

- 项目原名 **Agent Workbench**，现名 **MoyuBot**。
- **品牌显示名可改，技术标识符不可改**：CLI 仍叫 `aw`、数据目录仍是 `~/.agent-workbench`、
  环境变量仍是 `AGENT_WORKBENCH_HOME`、单元配置仍是 `.agent-workbench/bot.json`。
  改动会波及用户数据路径与脚本。
- 现有资产（`electron/icon*.png`、`tray-*.png`、`prototype/public/moyu-logo-{light,dark}-{64,128}.png`）
  均为阶段性资产，可整体替换。
- 好消息：品牌标已是**可替换插槽**——外观设置支持用户自带 logo，新标落地只需替换
  这组 PNG。
- **硬约束**：13 家执行器的名称与 logo 归各自所有者，界面内仅用于标识集成关系，
  不得复用或改绘。

---

## 七、待拍板

1. **「摸鱼」这个词留不留？** 它同时有「歇一会儿」和「上班偷懒」两种读法，现标语精准
   命中前者，但放官网首屏会滑向后者。另一条路是保留功能定位、另起中性名字。
2. **要不要独立中文品牌名**（英文名 + 中文名双轨）？
3. **Logo 路线**：延续现有 blob 吉祥物（亲和），还是走更几何、更「基础设施」的抽象标？
   两者调性差异很大。
4. **对外口径是否分级**：个人开发者社区（可玩）vs 企业介绍（需中性）要不要两套文案。
